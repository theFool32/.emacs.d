
* Emacs Configuration

** Installation
*** Installing Emacs
Install =Emacs= with one of below ways:
**** emacs-plus
#+begin_src bash
brew install emacs-plus@31 --with-native-comp --with-modern-purple-flat-icon
#+end_src
**** jimeh/emacs-builds
#+begin_src bash
brew tap jimeh/emacs-builds
brew install --cask emacs-app-monthly
#+end_src

or
#+begin_src bash
cd .emacs.d
make install_emacs
#+end_src

**** Compile from the source code
Check for [[https://github.com/theFool32/build-emacs-macos][theFool32/build-emacs-macos]]

*** Installing this configuration
#+begin_src bash
git clone --depth 1 https://github.com/theFool32/.emacs.d.git .emacs.d
#+end_src

*** Prepare
#+begin_src bash
cd .emacs.d
make custom
#+end_src

When the environment variables changed, you should update them with
#+begin_src bash
cd .emacs.d
make env
#+end_src

Enjoy hacking!

** Org Plans
Capture tasks in =gtd.org=, select their periods, and update the original
task's state. The task pool shows only unfinished entries from =gtd.org=.
The regular agenda uses the original file list: =gtd.org=, =diary.org=, and
=routine.org=. Project files are not included.

Plan selection and the =pd/pw/pm= capture templates add the =plan= tag.
Use =M-x org-tags-view= and search for =plan= to find planned tasks.
The tag remains while any =FOCUS_*= or =PLAN_*= selection is recorded,
including past periods, and is removed when no selections remain. Dates and
day/week/month distinctions continue to use the properties.

Use =SPC ;= to open day, week, and month plans, in that order. Every row refers
to the original task. Changes made in the agenda update its state and refresh
progress counts.
Only =DONE= counts as completed; =UNDONE= and =CANCELED= are shown separately.
Current plans and their progress counts use the daily agenda files and their
archives. The legacy =done.org= file is read only when explicitly viewing a
historical plan, so opening the startup agenda does not scan old records.

In an Org task or agenda, use these local-leader shortcuts:

| Keys | Action                         |
|------+--------------------------------|
| , v d | Toggle today's plan           |
| , v w | Toggle this week's plan       |
| , v m | Toggle this month's plan      |
| , v h | Review the past month/year    |

In the agenda, mark several tasks with =m=, then apply a plan shortcut once.
A mixed selection is added to the plan; if all selected tasks are already in
the current plan, they are removed. Selection does not change scheduled or
deadline dates. Week identifiers follow ISO weeks, starting on Monday.

For a new task, use =SPC x= and select =p d=, =p w=, or =p m= to capture
directly into today's, this week's, or this month's plan. Dates are filled
automatically. Planning does not automatically select parent periods or carry
unfinished tasks into the next period; select them explicitly when reviewing.

Use =, v h= to open the review directly, with no period or date prompts.
It shows a rolling month's closed-task records, followed by a
rolling year's monthly outcome totals and task records. Both ranges end
on today's date; month-end start dates are clamped to the last valid day.
The first and last calendar months in the yearly table can be partial.
Records are ordered by their =CLOSED= date, newest first; press =RET= to
visit the original task. =DONE=, =UNDONE=, and =CANCELED= are counted separately.
This review uses closing dates and current ended states, so legacy records
work without =FOCUS_*= or =PLAN_*= properties. Tasks without a =CLOSED= date
and tasks that are still open are outside these outcome totals. Reviewing
reads archives and =done.org= on demand and does not modify source files.
Refreshing the agenda recalculates the ranges and outcome totals.
No separate review file is created.

To archive a closed task, open its original Org entry and press =, D=.
The entire subtree is moved into =diary.org= under the =CLOSED= date's
=Archived= heading, keeping IDs and plan properties. The source and diary
are saved. This explicit command is the only plan-related operation that
writes to the diary; no existing diary or done entries are migrated.

Replanning a task retains its previous selections in =PLAN_DAYS=,
=PLAN_WEEKS=, and =PLAN_MONTHS=. Removing a selection removes only the current
period. Dates overwritten before this support was added cannot be recovered.

The old diary-goal capture templates, ACT tag planning, and cross-entry state
copier have been retired. Existing =diary.org= and =done.org= content is
preserved; plan selection and historical queries do not modify these files.
No old records are migrated or rewritten. Plan selection changes only
=gtd.org=. Reviews do not reconstruct past task states; their outcome counts use
closing dates and the recorded tasks' current ended states.
